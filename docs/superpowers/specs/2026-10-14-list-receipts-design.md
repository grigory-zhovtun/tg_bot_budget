# Сверка списка «Поступления и платежи» с фактом — дизайн

Дата: 14.10.2026 · Статус: на ревью у владельца · Порядок выкатки — раздел 11.

## 1. Зачем

Строки жёлтого списка во вкладке месяца (`O12:S19`: название, день, сумма со знаком,
валюта, сумма в сумах) сейчас учитываются **по дате**. До своего дня включительно
строка считается «впереди», после — что деньги уже на картах. Отсюда три ошибки:

- **ранняя зарплата считается дважды.** Пришла 29-го, а в списке стоит 30-е: 30-го она
  уже в остатке по `fact` и ещё «впереди». Лимит на день завышен на всю зарплату,
  прогноз «💳 Сумы — хватит до…» тоже ошибается;
- **поздняя зарплата роняет лимит.** Ждали 30-го, пришла 31-го: 31-го её нет ни
  «впереди», ни на картах;
- **не видно, что пришло.** На экране «План» нельзя понять, пришла ли зарплата и
  сколько.

Решение владельца (14.10.2026): в списке появляется колонка **«Пришло»**. Её заполняет
бот по листу `fact`. Бот считает лимит по той же сверке, которую записывает в колонку, а
формулы вкладки — по самой колонке. Поэтому после каждой сверки (раздел 7) таблица и
бот показывают одно и то же.

## 2. Что не делаем

- Число в «Пришло» руками не правится: колонка выводится из `fact`, и бот её
  перезаписывает. Правят источник — `fact` (деньги пришли, но не записаны) или саму
  строку списка (сдвинуть день, поменять сумму, удалить).
- Плановые расчёты не трогаем: «Должно быть по плану» (P3), «Останется к концу
  месяца» (P6), бюджет на день (P8), колонка «План» таблицы по дням (P22:P52) и плановый
  остаток в боте остаются по датам.
- Вкладки прошлых месяцев не меняем. Сверка идёт только для текущего месяца; на вкладке
  следующего месяца у строк нет статуса.
- Отдельных уведомлений нет — только строка в «📅 Впереди» и подписи на экране «План».

## 3. Колонка «Пришло»

- Заголовок «Пришло» — в колонке T строки заголовка списка (`T11` на нынешней вкладке),
  значения — в T тех же строк, что и строки списка (`T12:T19`). Колонка свободна,
  график вкладки начинается с U.
- Значение — сумма, которая реально пришла (или ушла) по строке, **в валюте строки и с
  тем же знаком**, что в колонке «Сумма»: поступление `+`, платёж `−`. Пусто — ничего
  не найдено.
- Пишет только бот, без формул (`RAW`).

## 4. Как бот находит поступления и платежи

Для каждой строки текущего месяца с днём `d`, суммой `Q` (со знаком) и валютой `C`:

**Окно.** С `d − 5` дней (не раньше 1-го) до последнего дня месяца.

**Поступление (`Q > 0`).** Кандидаты — доходы (`💰 ДОХОДЫ` без «нач остаток») в
валюте `C` с датой в окне.
- Каждый доход относится к одной строке: из строк-поступлений той же валюты, чьё окно
  содержит дату дохода, выбирается строка с ближайшим днём (при равенстве — более
  ранняя).
- `пришло = сумма отнесённых доходов`. Части складываются: зарплата, пришедшая
  несколькими переводами, наберётся целиком.
- Если доход отнесён не к той строке той же валюты (аванс сильно опоздал и пришёл
  рядом с зарплатой), подписи на экране будут неточными, но общая сумма «впереди»
  остаётся верной: недостающее просто числится у другой строки.

**Платёж (`Q < 0`).** Кандидаты — траты (без доходов и переводов между своими картами)
в валюте `C` с датой в окне, на сумму `|Q| ± 10 %`.
- Берётся одна трата: ближайшая по сумме, при равенстве — по дате.
- Одна трата закрывает не больше одной строки. Обычные покупки в той же валюте
  платежом не считаются.
- `пришло = −сумма траты`.

**Закрыта ли строка.** Строка закрыта, если `|пришло| ≥ 90 % |Q|`. Тогда «впереди» её
нет, сколько бы ни пришло. Иначе «впереди» остаётся недостающая часть `Q − пришло`;
день строки на это не влияет.

**Дата поступления** — дата последней отнесённой операции; нужна для подписи на
экране.

## 5. Что меняется в расчётах бота

Модуль сверки — новый `app/services/receipts.py`: чистые функции по `fact` и строкам
списка, I/O — отдельно.

- **Лимит на день.** Вместо «строки с днём ≥ сегодня» — сумма незакрытых остатков
  `Q − пришло` в сумах, по сверке на сегодня.
- **Столбики «Траты по дням».** Лимит прошлого дня `D` считается по операциям с датой
  раньше `D`, как было бы утром того дня.
- **Траты дня.** Из трат дня исключается трата, которой закрыт платёж из списка. Это
  заменяет нынешнее совпадение суммы «с точностью до 1 %».
- **🧊 Заморожено.** Из долларового остатка вычитаются только неоплаченные платежи в
  USD (`Q − пришло`). Значение на 1-е число, от которого считается изменение, как и
  раньше, учитывает все платежи в USD из списка.
- **Прогноз по сумам («💳 Сумы — хватит до…»).** Незакрытая строка в сумах добавляет
  остаток `Q − пришло` в свой день, а опоздавшая — сегодня.
- **«📅 Впереди»** (утреннее сообщение, `/today`, «Сводка»). Показывает две ближайшие
  незакрытые строки по дню, поэтому опоздавшие идут первыми с пометкой
  «⏳ ждём с dd.mm».
- **Без изменений:** плановый остаток на вечер вчера, плановая экономия месяца, «Должно
  быть по плану», советник.

## 6. Таблица: формулы вкладки

Меняются две ячейки блока прогноза. Обе сначала проверяются так: формула с пустой
колонкой «Пришло» даёт то же, что старая, пока у всех строк день ≥ сегодня.

**P5 «Лимит на сегодня».** В формуле меняется только слагаемое «список впереди».

Было:

```
SUMIFS($S$12:$S$19;$P$12:$P$19;">="&DAY($P$1))
```

Стало:

```
SUMPRODUCT(IFERROR(IF(ABS($T$12:$T$19)>=0.9*ABS($Q$12:$Q$19);0;
  $S$12:$S$19*(1-$T$12:$T$19/$Q$12:$Q$19));0))
```

**Q10 «🧊 Заморожено» (USD).** Меняется последнее слагаемое — платежи в USD впереди.

Было:

```
SUMIFS($Q$12:$Q$19;$R$12:$R$19;"USD";$Q$12:$Q$19;"<0";$P$12:$P$19;">="&DAY($P$1))
```

Стало:

```
SUMPRODUCT(IFERROR(($R$12:$R$19="USD")*($Q$12:$Q$19<0)*
  (ABS($T$12:$T$19)<0.9*ABS($Q$12:$Q$19))*($Q$12:$Q$19-$T$12:$T$19);0))
```

Пустые строки списка дают 0: пустая сумма не может быть меньше нуля, а для неё
`|пришло| ≥ 0`. Деление на пустую сумму ловит `IFERROR`.

**Где меняем.**
- Формулы и заголовок `T11` ставятся во вкладку текущего месяца один раз, после выкатки
  кода бота. Старые формулы сохранены выше — откат вставкой.
- Вкладки следующих месяцев — копии текущей и получают формулы сами. В новой копии бот
  сразу очищает «Пришло» у строк списка, иначе следующий месяц унаследует отметки
  прошлого.
- Блок ищется по заголовкам, как сейчас (`LIST_HEADER`, `TABLE_HEADER`), а не по номерам
  строк.

## 7. Когда бот пишет «Пришло»

- После каждой успешной записи в `fact` (`save_rows`: чат, Mini App, выписки), после
  `/undo` и `/fix` — фоновой задачей, ответ пользователю не ждёт.
- Каждый день в `month_tab_job` (и при запуске): так подхватывается то, что внесено
  мимо бота — правки в таблице, импорт выписок скриптом.
- Пишутся только изменившиеся ячейки текущей вкладки, одной записью
  `values_batch_update`. Одновременно идёт одна сверка (`bot_data["receipts_lock"]`).
- Сохранение плана: у строки списка, которую изменили или очистили, «Пришло» очищается
  в той же записи, затем запускается сверка.
- Ошибка чтения или записи пишется в лог, пользователю не показывается. Следующая
  сверка исправит.

## 8. Экран «План» и API

`GET /api/plan` и ответ сохранения: у строки списка появляются поля:
- `received` — сколько пришло, в валюте строки и со знаком, `null` — ничего;
- `received_on` — дата последней операции;
- `status` — `done` | `partial` | `waiting` | `future`.

Сверка считается при загрузке плана по уже прочитанному `fact`, то есть всегда свежая.

| Статус | Когда | Подпись под строкой |
|---|---|---|
| `done` | пришло ≥ 90 % | «✓ пришло 1,2 млн · 29.10», у платежа «✓ оплачено 500 USD · 17.10» |
| `partial` | пришло меньше 90 % | «пришло 50 000 из 100 000 RUB» |
| `waiting` | ничего, день уже прошёл | «⏳ ждём с 30.10» |
| `future` | ничего, день впереди | без подписи |

На вкладке следующего месяца у всех строк `future`. Итог «Поступления» на экране
остаётся плановым — суммой строк с «+».

## 9. Пограничные случаи

- **Строку изменили после того, как она закрылась** (новая сумма, другой день). Сверка
  считается заново, и строка может снова стать открытой.
- **Доход в валюте без курса.** `fact` такие строки уже пропускает с предупреждением в
  логе, сверка их не видит.
- **Строка с днём 31 в коротком месяце.** Считается последним днём месяца, как в прогнозе
  по сумам.
- **Текст или лишнее число в «Пришло».** Бот перезапишет при следующей сверке.
- **Вкладка без блока списка или без колонки T** (старые месяцы). Сверки нет, расчёты как
  раньше.
- **Доход пришёл в другом месяце** (зарплата за октябрь 1 ноября). Окно не выходит за
  месяц, строка остаётся открытой до конца месяца. Это видно как «⏳ ждём», и владелец
  может удалить строку.

## 10. Тесты

Python (pytest, данные-образцы без реальных сумм):
- сверка:
  - части зарплаты складываются;
  - ближайший день при двух строках одной валюты;
  - окно `d − 5` и конец месяца;
  - порог 90 %;
  - платёж ±10 %, одна трата закрывает одну строку;
  - мелкие покупки в той же валюте платёж не закрывают;
- лимит:
  - ранняя зарплата не считается дважды;
  - поздняя остаётся впереди;
  - частичное поступление;
  - лимиты прошлых дней в столбиках;
- траты дня без закрытого платежа; «Заморожено» после оплаты в USD; прогноз по сумам с
  опоздавшей строкой; «📅 Впереди» с опоздавшей первой;
- запись «Пришло»:
  - пишутся только изменившиеся ячейки;
  - пустая вкладка без списка не ломает сверку;
  - очистка в новой вкладке месяца;
  - очистка при правке строки в «Плане»;
- API: `received`, `received_on`, `status` для текущего и следующего месяца.

Фронтенд (Vitest): подписи под строками для четырёх статусов, платёж «оплачено».

Живая проверка после выкатки:
- формулы P5 и Q10 во вкладке при пустой «Пришло» совпадают со старыми значениями;
- после первой сверки P5 совпадает с лимитом `/today`, Q10 — с «🧊 Заморожено» в боте.

## 11. Порядок выкатки

1. PR с кодом → CI → merge → автодеплой Render → логи.
2. Формулы P5, Q10 и заголовок `T11` во вкладке текущего месяца — до первой сверки
   ботом. Пока «Пришло» пустая, новые формулы считают так же, как старые: у всех строк
   день ≥ сегодня.
3. Ручной запуск сверки (или запись любой операции) → «Пришло» заполнена → сверка P5 и
   Q10 с ботом.
4. Владелец смотрит «План» и утреннее сообщение 15-го (день аванса).

Если к моменту выкатки у какой-то строки день уже прошёл, шаг 2 меняет P5 сразу. Это
ожидаемо: строка снова «впереди», пока сверка её не закроет.
