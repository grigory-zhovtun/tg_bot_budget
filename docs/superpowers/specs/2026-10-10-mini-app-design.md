# Mini App бота бюджета — дизайн

Дата: 10.10.2026 · Статус: на ревью у владельца · Этапы реализации — раздел 13.

## 1. Зачем

Сейчас трата вводится в чате: карта → группа → подкатегория → сообщение «48000 латте».
Сводка месяца приходит текстом по командам /today, /plan, /subs. Mini App добавляет к чату:

- **ввод траты** крупными плитками и своей цифровой клавиатурой, без набора текста;
- **сводку** на одном экране: сколько можно сегодня, план-факт по группам полосками,
  график остатка по дням, заморозка, ближайшие поступления и подписки.

Чат остаётся как есть: SMS, скрины, выписки, /fix, /undo, утреннее сообщение.
Пользователи — владелец и жена (оба в `ALLOWED_USER_IDS`).

### Критерии готовности

1. Трата из Mini App записывается в лист fact той же строкой, что ручной ввод в чате
   (знак суммы, валюта по карте, дата). Формулы таблицы не меняются.
2. После записи из Mini App в чат приходит обычная сводка с «✏️ Исправить запись» и
   «↩️ Отменить запись»; /undo и /fix работают с этой записью.
3. Повторное нажатие «Записать» (двойной тап, повтор после обрыва сети) не создаёт
   вторую строку.
4. Числа сводки совпадают с таблицей: лимит — тот же расчёт, что /today (ячейка P5
   вкладки месяца); график — дневная таблица вкладки (колонки O:R под заголовком
   «Дата»); план-факт — колонки H:I вкладки.
5. Без действительной подписи Telegram или ссылки запуска API отвечает 401, на чужой
   Telegram ID — 403.
6. Бот в чате работает как раньше; CI зелёный (pytest, ruff, black и проверки
   фронтенда).

## 2. Что не делаем

- История записей и правка в приложении: в чате есть /fix и /undo. В приложении —
  только «Отменить» сразу после записи.
- Прошлые месяцы и тренды.
- Поступления со знаком «+» (возврат, перевод на карту) — остаются в чате. Группа
  «💰 ДОХОДЫ» в приложении доступна, как и в чате.
- Картинки из наборов кастомных эмодзи: веб-страница не умеет их показывать без
  скачивания стикеров. В приложении — обычные эмодзи из system!D.
- Офлайн-режим и темы оформления (кроме автоматических цветов Telegram).

## 3. Как открывается

| Вход | Откуда берётся | initData (подпись Telegram) |
|---|---|---|
| Кнопка «📱 Приложение» в нижней клавиатуре, под картами | бот добавляет её в клавиатуру карт | **нет** |
| Иконка на экране телефона | кнопка «📌 На экран телефона» в приложении или меню «⋯» | есть |
| Кнопка «Открыть» в профиле бота, ссылка `t.me/<бот>?startapp` | Main Mini App в @BotFather | есть |

Приложению, открытому кнопкой нижней клавиатуры, Telegram подпись не передаёт:
«It is empty if the Mini App was launched from a keyboard button»
([документация Mini Apps](https://core.telegram.org/bots/webapps)). Поэтому защита
строится на двух механизмах (раздел 5).

## 4. Архитектура

Один процесс Python на Render Web Service (тариф Starter) вместо фонового воркера:

```
Telegram ──POST /telegram──▶ ┌───────────────────────────────┐
                             │ uvicorn + Starlette           │
Mini App ──/api/*──────────▶ │  /telegram → очередь PTB      │──▶ Google Sheets
  (React) ◀── статика /app/ ─│  /api/*    → app/web/api.py   │
                             │  /health                      │
                             │  /app/     → webapp/dist      │
                             │ PTB Application (updater=None):│
                             │  обработчики, JobQueue         │
                             └───────────────────────────────┘
```

- Бот получает обновления вебхуком: `POST /telegram` проверяет заголовок
  `X-Telegram-Bot-Api-Secret-Token` и кладёт обновление в очередь PTB, дальше работают
  те же обработчики, что сейчас. Схема — из примера PTB
  [customwebhookbot](https://docs.python-telegram-bot.org/en/stable/examples.customwebhookbot.html)
  (вариант со Starlette). Встроенный `run_webhook` не подходит: к нему нельзя добавить
  свои маршруты.
- PTB-приложение запускается и останавливается вместе с сервером (lifespan Starlette).
  `post_init` (команды, проверка Gemini, наборы эмодзи) вызываем сами: без
  `run_polling`/`run_webhook` PTB его не вызывает. При старте — `set_webhook` с
  `allowed_updates=ALL_TYPES`.
- Секрет вебхука — `WEBHOOK_SECRET`, а если переменная пустая — выводится из токена бота
  (HMAC). В текущем коде секрет случайный при каждом старте; на веб-сервисе во время
  деплоя работают два экземпляра, и старый отказывал бы Telegram, пока тот не повторит
  доставку.
- Один процесс uvicorn, без нескольких workers: user_data и последняя запись живут в
  памяти процесса, как сейчас.
- Mini App — одна страница на React. Она собирается в `webapp/dist` и отдаётся тем же
  сервисом по `/app/`. У страницы и API один адрес: не нужен CORS, и защита Telegram
  «Mini App работает только со своего домена» (Bot API 10.2,
  [changelog](https://core.telegram.org/bots/api-changelog)) не мешает. Отключать её
  не будем.
- Локально (`LOCAL_RUN=true` или нет ни `WEBHOOK_URL`, ни `RENDER_EXTERNAL_URL`) бот, как
  сейчас, опрашивает Telegram.
- **Защита от двойного запуска.** Если у бота уже стоит вебхук, опрос не стартует, пока
  не задан `FORCE_POLLING=true`; в лог — ошибка, процесс ждёт и не уходит в цикл
  перезапусков. Без этой проверки PTB при старте опроса снимает вебхук, и рабочий сервис
  перестаёт получать сообщения. Проверка защищает и старый воркер при переезде, и
  локальный запуск с боевым токеном.

Новые модули:

| Файл | Что делает |
|---|---|
| `app/web/server.py` | Starlette-приложение: маршруты, жизненный цикл PTB, статика, заголовки |
| `app/web/auth.py` | проверка initData и ссылки запуска, кто пользователь |
| `app/web/api.py` | обработчики `/api/*` |
| `app/web/schemas.py` | Pydantic-модели запросов и ответов |
| `app/services/dashboard.py` | данные сводки из вкладки месяца и fact (чистые функции) |
| `webapp/` | React + TypeScript + Tailwind, сборка Vite |

Новые зависимости Python: `starlette`, `uvicorn` (версии закрепляем в requirements.txt).

## 5. Защита

Каждый запрос к `/api/*` несёт заголовок `Authorization` одного из двух видов.

1. `tma <initData>` — когда Telegram передал initData (иконка на экране, профиль бота,
   ссылка). Проверка по
   [документации](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app):
   ключ — `HMAC_SHA256("WebAppData", токен бота)`; строка проверки — все поля, кроме
   `hash`, по алфавиту, `key=value` через перевод строки; сравнение через
   `hmac.compare_digest`. `auth_date` — не старше 24 часов.
2. `Launch <токен>` — для кнопки в нижней клавиатуре. Бот кладёт в URL кнопки личный
   токен: `…/app/?launch=<user_id>.<время выдачи>.<подпись>`. Подпись — HMAC-SHA256
   ключом, выведенным из токена бота со своей меткой (не «WebAppData»). Срок — 30 дней.
   Клавиатура карт приходит заново после каждой записи, /start и смены карты, поэтому
   токен обновляется сам. Если срок вышел, приложение пишет «Кнопка устарела — отправьте
   /start».

Для обоих видов:

- ID пользователя проверяем по `ALLOWED_USER_IDS` при каждом запросе: убрали ID — доступ
  закрыт сразу.
- Смена токена бота отзывает все ссылки запуска: ключ выводится из токена.
- Токены и initData не пишем в логи. Access-лог uvicorn выключен: в нём была бы строка
  запроса с токеном.
- Авторизация идёт заголовком, а не cookie, поэтому подделка запросов с чужих сайтов
  (CSRF) не работает.
- Заголовки ответа: `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`.

Чем ссылка запуска слабее initData: она живёт 30 дней, а не сутки, и лежит в кнопке
чата. Открыть приложение по ней может тот, у кого есть доступ к вашему Telegram, — но
он и так может писать боту. По сети ссылка идёт только по HTTPS.

## 6. API

Все ответы — JSON. Ошибка: `{"error": {"code": "...", "message": "...", "fields": {...}}}`
(`fields` — только у 422).

### `GET /api/bootstrap`

Всё для экрана ввода. Данные из памяти бота, без обращения к таблице.

```json
{
  "user": {"id": 1, "first_name": "…"},
  "bot_username": "…",
  "today": "2026-10-10",
  "default_source": "VISA UZS",
  "sources": [{"name": "VISA UZS", "currency": "UZS"}],
  "groups": [{"name": "🍔 ЕДА", "emoji": "🍔", "title": "ЕДА",
              "subcategories": [{"name": "кофе", "icon": "☕"}]}]
}
```

`default_source` — карта, которую этот пользователь выбрал последней (в чате или
приложении), иначе карта последней записи в таблице.

### `POST /api/expenses`

```json
{"entry_id": "uuid", "source": "VISA UZS", "category": "🍔 ЕДА",
 "subcategory": "кофе", "amount": "48000", "comment": "латте", "day": "2026-10-10"}
```

`amount` — строка с числом: так центы долларовых карт не искажаются при переводе в
float. Проверки (422 с именем поля):

- карта, группа и подкатегория есть в справочнике бота;
- `0 < amount ≤ 10¹²`, не больше двух знаков после запятой;
- `comment` — до 200 символов;
- `day` — от сегодня минус 31 день до сегодня (по `ANALYTICS_TIMEZONE`).

Запись идёт общей с чатом функцией (раздел 9): та же строка, что при ручном вводе,
остатки карт, статус плана, сводка в чат. Ответ:

```json
{"status": "written", "rows": {"first": 4170, "last": 4170},
 "lines": ["✅ 48 000 UZS • 🍔 ЕДА (☕ кофе) • VISA UZS",
           "🟢 ☕ кофе: …", "💸 Сегодня осталось …"]}
```

- Повтор с тем же `entry_id` в течение 7 дней → `{"status": "duplicate", "rows": …}`,
  без записи.
- Таблица не ответила → 503 `sheets_unavailable`. `entry_id` при этом не запоминается,
  повтор безопасен.

### `POST /api/expenses/undo`

Отменяет последнюю запись этого пользователя (из чата или приложения) той же функцией,
что /undo: перед удалением она сверяет строку в таблице. Ответ —
`{"message": "…"}` с тем же текстом, что /undo пишет в чат.

### `GET /api/dashboard`

Читает вкладку месяца, fact и курсы и считает теми же функциями, что /today и /subs.

```json
{
  "status": "ok", "month": "Oct 26", "today": "2026-10-10",
  "limit": 0, "spent_today": 0, "left_today": 0,
  "plan_per_day": 0, "days_left": 22,
  "balance": 0, "planned_balance": 0,
  "frozen": {"amount": 0, "currency": "USD", "uzs": 0, "change": 0},
  "groups": [{"name": "🍔 ЕДА", "plan": 0, "fact": 0,
              "items": [{"name": "кофе", "icon": "☕", "plan": 0, "fact": 0}]}],
  "daily": [{"day": "2026-10-01", "plan": 0, "fact": 0}],
  "upcoming": [{"name": "…", "day": 15, "amount": 0, "currency": "UZS", "uzs": 0}],
  "subscriptions": [{"name": "…", "day": 3, "amount": 0, "currency": "USD",
                     "uzs": 0, "state": "charged"}]
}
```

- Суммы в сумах; `amount` у пунктов — в их валюте.
- `left_today = limit − spent_today`.
- `frozen` — `null`, если заморозка выключена (`FROZEN_CURRENCY=off`).
- `daily` — дневная таблица вкладки месяца: находим её по заголовку «Дата» в колонке O,
  как блок прогноза. План — на каждый день месяца, факт — по сегодня, дальше `null`.
  Таблицы нет — пустой список, и график не показываем.
- `subscriptions.state`: `charged` — списано в этом месяце, `twice` — дважды,
  `expected` — ещё ждём, `missed` — день прошёл, а списания нет.
- Вкладки месяца нет → `{"status": "no_month_tab"}`. Нет блока прогноза →
  `{"status": "no_forecast"}` и только `groups`.

### Служебные маршруты

- `POST /telegram` — вебхук; неверный секрет → 403.
- `GET /health` — 200 без обращения к таблице, для проверки Render.
- `GET /app/…` — статика: `index.html` без кэша, файлы с хэшем в имени — кэш на год.

## 7. Экран «Ввод»

Открывается первым.

1. **Карта** — ряд чипов, выбрана карта последней записи.
2. **Группа** — плитки по две в ряд: крупный эмодзи и название.
3. **Подкатегория** — плитки по три в ряд с иконками из system!D. Системная кнопка
   «Назад» Telegram возвращает к группам.
4. **Сумма** — крупные цифры и своя клавиатура: 1–9, 0, 000, ⌫, запятая — только у карт
   не в сумах. Ниже поле комментария и дата «Сегодня»; тап по дате открывает выбор,
   до 31 дня назад.
5. **Запись** — нижняя кнопка Telegram «Записать 48 000 UZS», активна, когда сумма больше
   нуля. После нажатия: индикатор на кнопке → запрос → вибрация «успех» → плашка с
   ответом (`lines`) и кнопкой «↩️ Отменить» → снова группы, карта остаётся.

При ошибке — вибрация «ошибка» и текст под суммой. Введённое не теряется; «Повторить»
отправляет запрос с тем же `entry_id`.

## 8. Экран «Сводка»

Сверху вниз:

1. **Можно сегодня** — `left_today` крупно (красным, если меньше нуля), под ним
   «лимит … · потрачено …» и полоска.
2. **На картах** — факт против плана на вчерашний вечер и разница.
   **🧊 Заморожено** — сумма в валюте и изменение с 1-го числа.
3. **План-факт по группам** — полоски: зелёная до 80 % плана, жёлтая от 80 до 100 %,
   красная сверх плана, серая — трата вне плана. Тап по группе раскрывает подкатегории.
4. **Остаток по дням** — линия плана на весь месяц и линия факта по сегодня. Рисуем SVG
   сами, без библиотек графиков.
5. **Впереди** — поступления и крупные платежи жёлтого списка.
6. **Подписки** — по дню месяца, с состоянием: списано, ждём, дважды, не было.

Наверху — кнопка «Обновить». Пока таблица отвечает, вместо блоков серые заглушки.
Внизу — «📌 На экран телефона», если ярлыка ещё нет (`checkHomeScreenStatus`).

Как создаётся ярлык:

- приложение открыто с initData → сразу `addToHomeScreen()`;
- открыто кнопкой нижней клавиатуры → открываем `t.me/<бот>?startapp=home`. Это то же
  приложение через Main Mini App, уже с initData, и там сразу предлагаем ярлык.

Так ярлык всегда ведёт на вход с подписью Telegram, а не на ссылку с 30-дневным
токеном.

## 9. Изменения в боте

- **Клавиатура карт** (`generate_sources_keyboard`): последней строкой — кнопка
  «📱 Приложение» (web_app, синяя) с личной ссылкой запуска. Только в режиме
  веб-сервиса; при локальном опросе кнопки нет.
- **Общая запись**: `_save_rows(update, …)` → `save_rows(context, chat_id, rows, skipped,
  fingerprint)`. Функция возвращает, сколько записано, номера строк и строки сводки.
  Чат и API вызывают одну функцию; `show_main_menu` отправляет сообщения по `chat_id`, а
  не ответом на сообщение. Для API контекст пользователя —
  `CallbackContext(application, chat_id=user_id, user_id=user_id)`: у него те же
  user_data, что у чата, — последняя запись для /undo и недавние записи для защиты от
  повторов (`entry_id` хранится как `app:<uuid>`).
- **Строка ручного ввода**: из `manual_row` выделяем построение строки по готовой сумме,
  его вызывает и API.
- **main()**: веб-режим (uvicorn + Starlette) или опрос с защитой из раздела 4.
- **Документация**: в README и CLAUDE.md — веб-сервис, Mini App, `FORCE_POLLING`,
  локальная разработка фронтенда.

## 10. Фронтенд

- `webapp/`: Vite, React (функциональные компоненты и хуки), TypeScript в режиме
  `strict`, Tailwind. Версии закреплены в `package-lock.json`.
- Telegram: официальный скрипт `telegram-web-app.js` и своя типизированная обёртка
  `src/telegram.ts` (ready, expand, тема, MainButton, BackButton, HapticFeedback, ярлык,
  initData) — без `any`.
- Цвета — переменные темы Telegram (`--tg-theme-bg-color` и другие) в токенах Tailwind:
  светлая и тёмная тема без настроек. Отступы от краёв — `--tg-content-safe-area-inset-*`.
  Свои цвета — только у статусов (зелёный, жёлтый, красный), подобранные под обе темы.
- Деньги форматируем как бот: пробелы между разрядами, «млн» для крупных сумм.
- `npm run dev` — страница в обычном браузере с тестовыми данными, без Telegram и
  сервера: для вёрстки.

## 11. Ошибки

| Ситуация | API | Что видит пользователь |
|---|---|---|
| нет или неверная подпись, initData старше суток | 401 `unauthorized` | «Откройте приложение заново из бота» |
| ссылка запуска старше 30 дней | 401 `launch_expired` | «Кнопка устарела — отправьте /start» |
| ID не в списке | 403 `forbidden` | «Нет доступа» |
| неверное поле | 422 `validation` и `fields` | поле подсвечено |
| таблица не ответила | 503 `sheets_unavailable` | «Таблица не ответила» и «Повторить» |
| нет вкладки месяца | 200 `no_month_tab` | «Вкладки месяца нет — бот создаёт её 1-го числа» |
| ошибка в обработчике бота | — | как сейчас: `on_error` и лог |

Ошибки API пишем в лог с ID пользователя, без тела запроса и заголовков.

## 12. Тесты

Python (pytest, как сейчас; HTTP — через Starlette `TestClient`):

- initData: верная подпись; изменённое поле; старый `auth_date`; нет `hash`; поле
  `signature` входит в строку проверки (исключается только `hash`).
- Ссылка запуска: верная; чужая подпись; просрочена; ID не в списке.
- `/api/bootstrap`; `/api/expenses`: запись, 422 по каждому полю, повтор `entry_id`, 503
  без запоминания; `/api/expenses/undo`; `/api/dashboard` на данных-образцах: лимит
  равен расчёту /today, дневная таблица, `no_month_tab`.
- `/telegram`: секрет, обновление попадает в очередь; `/health`; статика.
- Чат: сводка после записи не изменилась (существующие тесты сообщений переводим на
  `save_rows`); клавиатура карт с кнопкой приложения; опрос не стартует при стоящем
  вебхуке.

Фронтенд (Vitest и Testing Library): клавиатура суммы, форматирование денег, выбор
заголовка авторизации, разбор ошибок API, путь «группа → подкатегория → сумма → запись»
с подменённым fetch. Плюс `tsc --noEmit`, eslint, prettier и `vite build`. В CI —
отдельная задача для `webapp/`.

  отменить;

## 13. Переезд на Render и этапы

Каждый этап — отдельный PR: ветка → тесты → PR → CI → merge → автодеплой → логи.

**Этап 1 — веб-сервис и вебхук.** Сервер Starlette, `/telegram`, `/health`, защита
опроса, `app/web/auth.py` с тестами. API на этом этапе ещё нет.

1. Merge: воркер передеплоится и продолжит опрос — поведение не меняется.
2. Создаю Web Service: Starter, тот же регион, ветка main, запуск `python -m app.main`,
   проверка `/health`, автодеплой.
3. **Вы** копируете в него переменные окружения воркера. Имена дам списком; значения
   секретов я не вижу и не ввожу.
4. Сервис стартует и ставит вебхук. Опрос воркера получает отказ Telegram, а защита не
   даст воркеру снять вебхук при перезапуске. Приостанавливаю воркер (Suspend в Render).
5. Проверка: в логах — вебхук и ваши сообщения, бот отвечает как раньше.
   Откат: приостановить веб-сервис, на воркере задать `FORCE_POLLING=true` и запустить
   его снова (Resume).
6. Через неделю без сбоев удаляю воркер — только после вашего «да».

Стоимость: веб-сервис Starter стоит столько же, сколько воркер
([цены Render](https://render.com/pricing)). Пока работают оба, оплата идёт за оба
пропорционально времени.

**Этап 2 — ввод.** `save_rows`, `/api/bootstrap`, `/api/expenses`, `/api/expenses/undo`,
каркас `webapp/`, экран «Ввод», кнопка в клавиатуре карт. Команда сборки на Render:
`pip install -r requirements.txt && npm --prefix webapp ci && npm --prefix webapp run build`.
Node в Python-окружении Render есть
([native runtimes](https://render.com/docs/native-runtimes)); если сборка не пройдёт —
Dockerfile из двух стадий.

**Этап 3 — сводка.** `app/services/dashboard.py`, `/api/dashboard`, экран «Сводка» с
графиком.

**Этап 4 — ярлык и доступ жене.** Main Mini App (настраиваете вы в @BotFather),
«📌 На экран телефона», ID жены в `ALLOWED_USER_IDS`, её карты в system!F, документация.

## 14. Риски

- **Ярлык из приложения, открытого кнопкой клавиатуры**, в документации Telegram не
  описан — поэтому ярлык делаем через Main Mini App (раздел 8). Переход по
  `t.me/<бот>?startapp=home` изнутри приложения тоже проверяем на iOS и Android в
  этапе 4. Запасной путь — меню «⋯» → «Добавить на экран» в приложении, открытом из
  профиля бота.
- **Два экземпляра во время деплоя** (Render переключает трафик после `/health`): если
  деплой придётся ровно на 08:00, утреннее сообщение может прийти дважды. Принимаем.
- **Секреты при переезде** переносите вы: я не читаю и не ввожу токены и ключи.
- **Карта по умолчанию у жены** — из её последней записи. Общая «последняя карта» бота
  после перезапуска может оказаться её картой — так же, как сейчас в чате.
