# Календарь записей во вкладке «Прогноз» — дизайн

Дата: 15.10.2026 · Статус: одобрена владельцем, уточнена при планировании · Шаг 2 из 2 (шаг 1 — вкладка «Прогноз»,
`2026-10-15-forecast-tab-design.md`, в проде).

## 1. Зачем

Владелец хочет планировать траты по дням внутри статей плана — разовые («в субботу дети
идут в детский центр, ~320 000, ДЕТИ / развитие») и повторяющиеся («кофе каждый день
~30 000») — и сразу видеть их в «Прогнозе»: на вечер какого дня сколько останется.

Решения владельца (15.10.2026):

- запись — часть плана статьи, назначенная на день; план статей остаётся главным бюджетом;
- эффекты записи: резерв в статье, закрытие фактом, подсказка суммы из истории, разовые
  и повторяющиеся записи;
- записи хранятся на отдельном листе «Календарь» той же таблицы;
- в календаре только траты; поступления остаются в жёлтом списке;
- повторы: каждый день, по дням недели, раз в месяц;
- разовые записи меняют обе линии прогноза, повторы — только «по плану»;
- запись больше остатка статьи считается целиком, приложение предупреждает о превышении;
- экран — во вкладке «Прогноз»: сетка месяца вместо ленты недели (в клетке остаток на вечер
  и сумма записей дня), карточка дня с записями, внизу список записей месяца.

## 2. Что не делаем

- Поступления в календаре.
- Повтор «раз в две недели», дата окончания повтора, пропуск одного дня повтора — запись
  правят или удаляют.
- Перенос прошедших незакрытых записей: не купили кофе вчера — этой траты не было.
- Записи в чате бота и в утреннем сообщении (кроме того, что карточка «💳 Сумы» их учитывает).
- Правку записей из вкладки «План», напоминания.
- Прогноз дальше последнего дня месяца: записи на следующие месяцы хранятся и войдут в
  прогноз, когда наступит их месяц (в списке «Записи» они видны сразу).

## 3. Лист «Календарь»

Бот создаёт лист при первой записи. Строка 1 — шапка, дальше одна строка на запись:

| Колонка | Шапка | Что | Пример |
|---|---|---|---|
| A | ID | код записи из 6 символов: первый — буква `a–z`, дальше `a–z`, `0–9`; задаёт бот | `k7f2qa` |
| B | Дата | день разовой записи или первый день повтора | 17.10.2026 |
| C | Повтор | `нет`, `каждый день`, `по дням недели`, `раз в месяц` | `нет` |
| D | Дни | для «по дням недели»: дни через пробел — `пн вт ср чт пт сб вс` | `пн ср` |
| E | Группа | группа справочника, как в `fact` | 👶 ДЕТИ |
| F | Подкатегория | подкатегория справочника | развитие |
| G | Валюта | валюта статьи | UZS |
| H | Сумма | больше нуля, в валюте статьи | 320000 |
| I | Название | необязательно; пусто — показывается подкатегория | Детский центр |
| J | Кто | имя того, кто завёл или правил запись | Иван |

- У записи «раз в месяц» число берётся из даты; 31-е в коротком месяце — его последний день.
- Строки без ID, даты, статьи или суммы, с неизвестным повтором или днём недели, без дней у
  «по дням недели» бот пропускает и пишет в лог; остальные записи считаются. Дата читается
  и как текст «ДД.ММ.ГГГГ», и как дата таблицы; повтор — без учёта регистра; число, которое
  не может быть датой (сумма в колонке даты), — битая строка, а не ошибка всего листа.
- ID уникален. Строка с ID, который уже встретился выше (строку скопировали руками),
  пропускается и пишется в лог: правка и удаление по ID берут первую строку. У копии нужно
  поменять ID на новый — 6 символов, первый — буква.
- Лист можно править руками: бот перечитывает его не реже раза в минуту (раздел 5.4).

## 4. Модель

Сегодня — `t`, последний день месяца — `e`, оставшиеся дни `left = e − t + 1`. Статья —
пара (подкатегория, валюта), как во вкладке месяца; группа записи на расчёт не влияет.

### 4.1 Дни записи

Запись раскладывается на **вхождения** — дни месяца, на которые она приходится:

- `нет` — её дата;
- `каждый день` — каждый день начиная с даты;
- `по дням недели` — дни недели из колонки D начиная с даты;
- `раз в месяц` — число из даты (не раньше самой даты).

Для прогноза нужны вхождения с `t` по `e`; разовые записи с датой с `t − 14` — ещё и для
темпа (4.5).

### 4.2 Закрытие фактом

Операции — строки `fact` групп трат (без «💰 ДОХОДЫ» и «💳 СЧЕТА»), как у темпа.

1. **Разовая запись заранее.** Её закрывает одна операция той же статьи на сумму записи
   ±10 % с даты записи минус 3 дня по дату записи (но не позже сегодня). Записи берутся по
   порядку дат; операция закрывает одну запись; из кандидатов — ближайшая по сумме, потом по
   дате. Операции, которыми уже закрыты платежи жёлтого списка, не берутся.
2. **Сегодня.** Траты статьи за сегодня (кроме операций из п. 1 и закрывших платежи
   списка) засчитываются в её сегодняшние вхождения: покрытая доля
   `f = min(траты статьи сегодня / Σ сегодняшних вхождений статьи; 1)`. Остаток вхождения —
   `сумма × (1 − f)`; при `f ≥ 0,9` вхождения статьи закрыты («✓ потрачено»).
3. Будущие вхождения открыты, если разовую запись не закрыли заранее (п. 1).
4. Прошедшие вхождения в прогноз не попадают.

У вхождения два «открыто», как у плана и событий в спеке прогноза:

- **на утро** — без сегодняшних операций: сегодняшнее и будущее — вся сумма, разовая запись,
  закрытая заранее операцией по вчера, — 0. Из него считается резерв (4.3), поэтому план
  в день за день не меняется;
- **на сейчас** — с сегодняшними: сегодняшнее — остаток по п. 2, разовая запись, закрытая
  заранее (в том числе сегодня), — 0. Это события линий (4.4, 4.5) и суммы на экране.

### 4.3 Резерв в статье и «сверх плана»

Для статьи `a`:

- `остаток_a` = max(план − факт с 1-го по вчера; 0) — как в спеке прогноза (3.3); статьи нет
  во вкладке — 0;
- `записи_a` = Σ открытого **на утро** у вхождений статьи с `t` по `e`;
- `резерв_a` = min(`записи_a`; `остаток_a`); `сверх_a` = `записи_a` − `резерв_a`.

`сверх_a > 0` — у записей статьи метка «сверх плана», в прогнозе они идут целиком.

### 4.4 Линия «по плану»

- По дням раскладывается `Σ (остаток_a − резерв_a)` по статьям валюты минус неоплаченные
  платежи списка — с правилом переноса между валютами из спеки прогноза (3.3).
- Открытое **на сейчас** у вхождений всех записей — события в свой день, с минусом.
- Траты сегодня для «в день» (спека прогноза 3.6) — без операций, закрывших платежи списка
  и разовые записи, и без засчитанного в сегодняшние вхождения (4.2, п. 2).

### 4.5 Линия «по темпу»

- События — платежи списка (как сейчас) и открытое на сейчас у вхождений **разовых**
  записей; повторы в темп не добавляются: такие траты уже в средних за 14 дней.
- Из окна темпа (`t − 14 … t − 1`) исключаются операции, закрывшие разовые записи (4.2,
  п. 1), — как платежи списка.
- Траты сегодня для темпа — без засчитанного только в сегодняшние **разовые** вхождения:
  кофе по повтору — обычная трата дня.

### 4.6 Карточка «💳 Сумы»

Карточка — линия «по темпу» в сумах (спека прогноза 3.10), поэтому учитывает разовые
записи в сумах. Утреннее сообщение, `/today`, «Сводка», ответ после записи траты и советник
получают записи календаря так же, как вкладка «Прогноз», — «хватит до» и прогноз называют
один день.

### 4.7 Подсказка суммы

По статье, по операциям групп трат с суммой больше нуля:

- **обычно** — медиана операций за 90 дней до сегодня;
- **в прошлый раз** — последняя операция;
- **в среднем в день** — сумма за 30 дней до сегодня / 30.

Сумы округляются до тысячи, остальные валюты — до целых. Нет операций — подсказки нет.
Окно показывает «обычно» и «в прошлый раз» для разовой, недельной и месячной записи и
«в среднем в день» — для «каждый день».

### 4.8 Пример (условные цифры)

Сегодня 15-е, 17 дней до конца месяца.

- «ДЕТИ / развитие»: план 1,2 млн, потрачено 400 000, остаток 800 000. Записи: детский центр
  320 000 в субботу 17-го (разовая) и кружок 80 000 по пн и ср (20, 22, 27, 29 → 320 000).
  `записи` = 640 000, резерв 640 000, по дням идут 160 000 (≈ 9 400 в день). «По плану»
  опускается на 320 000 в субботу и на 80 000 по пн и ср; «по темпу» — на 320 000 в субботу.
- «ЕДА / кофе»: остаток 480 000, повтор 30 000 каждый день × 17 = 510 000 → `сверх` 30 000:
  в прогнозе все 510 000, у записи метка «сверх плана».
- Сегодня куплен кофе на 25 000: `f` = 25 000 / 30 000 ≈ 0,83 — вхождение ещё открыто,
  на сейчас остаток 5 000; в «обычные траты дня» линии «по плану» эти 25 000 не идут.
  Резерв и план в день не меняются: на утро вхождение — все 30 000.
- Детский центр оплачен сегодня одной операцией на 320 000: запись закрыта, события нет,
  операция не входит ни в траты дня, ни в темп; резерв на утро тот же — план в день не
  подскакивает.

## 5. Данные и API

### 5.1 `GET /api/forecast` — дополнения

К ответу спеки прогноза (4.2) добавляется:

```json
{
  "rates": {"USD": 12000, "RUB": 150},
  "currencies": [
    {
      "code": "UZS",
      "records": [
        {"id": "k7f2qa", "day": 17, "name": "Детский центр", "group": "👶 ДЕТИ",
         "subcategory": "развитие", "repeat": "once", "amount": 320000, "open": 320000,
         "done": false, "over": false},
        {"id": "m3a9zt", "day": 15, "name": "Кофе", "group": "🍔 ЕДА",
         "subcategory": "кофе", "repeat": "daily", "amount": 30000, "open": 5000,
         "done": false, "over": true}
      ]
    }
  ],
  "calendar": [
    {"id": "m3a9zt", "date": "2026-10-01", "repeat": "daily", "weekdays": [],
     "group": "🍔 ЕДА", "subcategory": "кофе", "currency": "UZS", "amount": 30000,
     "name": "Кофе", "author": "Иван", "month_total": 485000, "booked": 510000,
     "over": true}
  ],
  "articles": [
    {"group": "👶 ДЕТИ", "subcategory": "развитие", "currency": "UZS",
     "plan": 1200000, "rest": 800000, "booked": 640000}
  ],
  "hints": {"развитие|UZS": {"typical": 320000, "last": 300000, "per_day": 21000}}
}
```

- `records` — вхождения с сегодня по конец месяца в валюте: `amount` — сумма записи, `open` —
  открытое на сейчас (4.2), `done` — закрыто (`open` 0), `over` — у статьи `сверх > 0`.
  `repeat`: `once`, `daily`, `weekdays`, `monthly`.
- `calendar` — все повторы и разовые записи с датой с сегодня, в том числе в следующих
  месяцах: любую запись можно открыть, поправить и удалить, даже если до конца месяца у неё
  нет дней (месячная после своего числа). Сначала повторы по дате начала, потом разовые по
  дате. `weekdays` — номера дней ISO (пн = 1 … вс = 7); `month_total` — Σ открытого на сейчас
  с сегодня до конца месяца (0 — дней нет или всё закрыто); `booked` — доля записи в
  `записи_a` (на утро), из неё окно считает предупреждение о превышении.
- `articles` — статьи трат вкладки месяца и статьи записей без строки во вкладке (`plan` 0):
  `rest` — `остаток_a`, `booked` — `записи_a`.
- `hints` — по статьям с операциями за 90 дней, ключ `подкатегория|валюта`.
- `rates` — курсы таблицы к суму, для сумм записей в клетках вида «Всего».

### 5.2 Добавить, поправить, удалить

- `POST /api/calendar` — новая запись. Тело:
  `{"entry_id": "<uuid>", "date": "2026-10-17", "repeat": "once", "weekdays": [],
  "group": "👶 ДЕТИ", "subcategory": "развитие", "currency": "UZS", "amount": "320000",
  "name": "Детский центр"}`. Повтор с тем же `entry_id` новую строку не пишет.
- `PUT /api/calendar/<id>` — то же тело без `entry_id`; правит строку записи целиком.
- `DELETE /api/calendar/<id>` — удаляет строку записи (у повтора — весь повтор).

Каждый отвечает свежим прогнозом (`ForecastOut`). После `POST`, `PUT` и `DELETE` второму
пользователю в чат уходит заметка — как у плана, имя через тире, без рода:
«📅 Иван — новая запись: 17.10 Детский центр 320 000 UZS (ДЕТИ / развитие)»,
«📅 Иван — запись изменена: …», «📅 Иван — запись удалена: …»; без имени — «📅 Новая запись:
…»; у повтора вместо даты — правило («каждый день с 15.10», «пн ср с 20.10», «15-го каждого
месяца»).

### 5.3 Проверки и ошибки

- `422 validation`, сообщения у полей:
  - `date` — «Дата — не раньше сегодня и не дальше чем через год». У `PUT` повтора дата
    может остаться прежней, если она раньше сегодня;
  - `amount` — «Сумма — больше нуля, до двух знаков после запятой»;
  - `group` — «Такой статьи нет — обновите приложение» (нет в справочнике, или группа
    «💰 ДОХОДЫ» или «💳 СЧЕТА»); `subcategory` — «Такой подкатегории нет — обновите
    приложение», как у траты;
  - `repeat` — «Такого повтора нет — обновите приложение»;
  - `currency` — «Такой валюты нет у карт»;
  - `weekdays` — «Выберите дни недели» (пусто при «по дням недели»; у других повторов
    должно быть пусто);
  - `name` — «Название — до 60 символов».
- `404 record_not_found` — «Запись уже удалили — обновите прогноз».
- `503 sheets_unavailable` — тот же текст, что у «Сводки».

### 5.4 Чтение и запись листа

- `GoogleSheetsService.get_calendar()` — значения листа (UNFORMATTED) одним запросом; копия
  живёт 60 секунд; запись листа ботом её сбрасывает. Чтение, во время которого бот записал
  в лист, копией не становится: лист могли прочитать до записи. Листа нет — записей нет.
- Новая запись — строкой в конец листа значениями как есть (`RAW`): дата — текстом
  «ДД.ММ.ГГГГ», сумма — числом. Так таблица не превращает текст в формулу или дату, а ID —
  в число. Листа нет — бот создаёт его с шапкой. Запись не повторяется при сбое: потерянный
  ответ записал бы строку дважды.
- Правка и удаление — по ID: бот читает колонку A, находит строку с этим ID и пишет всю
  строку A:J (`RAW`) или удаляет её (удаление тоже без повтора). Строки с таким ID нет —
  `404`.
- Записи в лист — по одной (один замок на приложение): иначе удаление строки выше между
  поиском строки и записью сдвинуло бы строки, и правка легла бы на другую запись.

## 6. Экран

Вкладка «Прогноз», сверху вниз:

1. **Переключатели** вида и единиц, **предупреждение** — без изменений.
2. **Сетка месяца** вместо ленты недели. Заголовок — «<Месяц>». Недели — с текущей по
   последнюю неделю месяца; дни до сегодня в текущей неделе серые, дни следующего месяца не
   показываются. В клетке будущего дня и сегодня: число; остаток на вечер по плану в виде
   (сумы — в млн с одним знаком, доллары и рубли — целыми; минус — красным); красная сумма
   открытого на сейчас у записей дня в виде («−350к», во «Всего» — по `rates` в сумах или долларах);
   цветные точки строк жёлтого списка. Сегодня обведено, выбранный день закрашен; нажатие
   выбирает день. Подпись: «В клетке — сколько будет вечером, <единица> (по плану), и записи
   дня».
3. **Карточка дня**: как сейчас, плюс «Записи на день» — ▼ разовая или ↻ повтор, название,
   сумма открытого (у закрытой — «✓ потрачено» и сумма серым), «статья · правило»; метка
   «сверх плана». Для сегодня и будущих дней — «＋ Запланировать на <число месяца>».
4. **График** — без изменений, ▼ в дни открытых разовых записей (повторы не отмечаются:
   кофе каждый день поставил бы ▼ под каждым днём).
5. **«Записи»**: «Повторы» (название, сумма, «статья · правило», у повтора с будущим началом —
   «с <дата>», если в месяце ещё есть его дни — «· до <конец> — <month_total>») и «Разовые» с
   сегодняшнего дня, в том числе на следующие месяцы (дата, название, сумма, статья;
   оплаченная — «✓» и сумма серым); «＋ Новая». Записей нет — «Запланируйте траты на дни —
   прогноз вычтет их в свой день.»
6. **«По валютам»** и пояснение — без изменений.

**Окно записи** (снизу, поверх экрана):

- заголовок «Запись на 17 октября» или «Запись», «✕» — закрыть без сохранения;
- **Статья**: валюта (валюты карт), группы справочника без «💰 ДОХОДЫ» и «💳 СЧЕТА»,
  подкатегории группы; под ними «В статье осталось <rest> из <plan>» (статьи нет во вкладке —
  «Статьи нет в плане месяца»);
- **Сумма**: кнопки-подсказки (4.7) над суммой — нажатие подставляет сумму, — сумма и
  клавиатура, как при вводе траты;
- **Название** (необязательно);
- **Повтор**: «Разово · Каждый день · По дням недели · Раз в месяц»; для «по дням недели» —
  дни «пн … вс»;
- **Дата** у разовой, **Начало** у повтора (по умолчанию — выбранный день; у правки повтора
  с началом в прошлом прежняя дата остаётся); пустое поле (iOS «Сбросить») дату не меняет;
- **предупреждение**, если записей в статье станет больше остатка: «⚠️ План статьи
  «ДЕТИ / развитие» будет превышен на 120 000 сум» — приложение считает вхождения правки
  (4.1) и сравнивает `booked` без этой записи плюс новые вхождения с `rest`;
- кнопка «Запланировать» (новая) или «Сохранить» и «Удалить запись» (существующая);
  удаление — со второго нажатия: «Удалить запись» → «Удалить насовсем». Пока запрос идёт,
  кнопки выключены: двойное нажатие шлёт один запрос.

Нажатие на запись в карточке дня или в списке открывает её в окне. Окно закрывается после
ответа сервера; ошибки полей — под полями, остальные — над кнопкой. Каталог групп и валюты
карт приложение берёт из `/api/bootstrap`.

## 7. Затронутые части

- `app/services/calendar.py` — новый: разбор листа (`CalendarRecord`), вхождения, закрытие,
  подсказки — без сети.
- `app/services/forecast.py` — записи в `currency_forecast` и `month_forecast` (разделы
  4.3–4.5), статьи и вхождения в ответе модели.
- `app/services/day_budget.py`, `app/services/runway.py`, `app/services/dashboard.py`,
  `app/services/analytics_service.py`, `app/services/plan_advice.py` — записи для карточки
  «💳 Сумы».
- `app/services/google_sheets.py` — `get_calendar` с копией на 60 с, добавление, правка и
  удаление строки по ID, создание листа.
- `app/web/schemas.py`, `app/web/api.py` — дополнения `ForecastOut`, `CalendarIn`,
  `POST/PUT/DELETE /api/calendar`, заметка второму пользователю.
- `webapp/src/forecast/` — сетка месяца вместо ленты, записи в карточке дня, список записей,
  окно записи, вхождения правила для предупреждения; `App.tsx` передаёт `boot` во вкладку.
- `README.md`, `CLAUDE.md` репозитория — абзац о календаре.

## 8. Проверка и выпуск

- **Модель:** вхождения всех повторов (начало в прошлом и будущем, 31-е в коротком месяце,
  дни недели), закрытие разовой заранее и только одной операцией, сегодняшнее покрытие
  (частичное и ≥ 90 %), резерв на утро — план в день не меняется от сегодняшней оплаты
  записи, «сверх плана», статья без строки во вкладке, линия «по
  плану» с записями и платежами списка, темп без операций разовых записей, повтор не в темпе,
  траты сегодня без засчитанного, подсказки.
- **Лист:** создание листа, добавление, правка и удаление по ID, сдвинутая строка, нет ID —
  `404`, копия на 60 с и её сброс.
- **API:** форма ответа, проверки полей, повтор `entry_id`, `404`, заметка второму
  пользователю, `503`.
- **Приложение:** сетка (клетки, серые дни, выбор дня, суммы в виде «Всего»), записи в
  карточке, список, окно (подсказки, повтор, дни недели, предупреждение, сохранение,
  удаление, ошибки полей).
- **Выпуск:** один PR, автодеплой Render; владелец заводит запись с телефона — сверка строки на
  листе «Календарь» и прогноза, «хватит до» в «Сводке» совпадает с днём ухода сумов в минус.
